# AnimeShelf 使用指南

[返回项目介绍](../README.md)

本指南介绍如何建立本地媒体库、整理作品资料与收藏，以及保护文件和备份。当前获取方式见[项目首页](../README.md)；源码环境与构建命令见[开发文档](DEVELOPMENT.md)。

## 1. 启动与添加媒体库

从源码运行时，在浏览器打开启动器显示的本机地址，并保持服务运行。自行构建的 Windows 便携版可直接运行 EXE。首次启动使用新的数据目录；不要直接覆盖其他版本的已有数据。

1. 进入侧栏「全部媒体」，点击「添加媒体库」。
2. 填写媒体库名称和已经存在的文件夹绝对路径，例如 `D:\Media\Anime`。
3. 选择「动画」或「影视」并添加。这个类型是媒体库的默认分类，之后仍可调整单个作品。

也可在「设置 → 媒体库」填写名称和路径后点击「添加」；这个简化入口默认建立动画媒体库。需要在添加时选择影视类型，请使用「全部媒体」的入口。

添加媒体库只记录位置，不复制媒体文件，也不会代替扫描。请保留原文件所在目录，避免在软件运行时随意移动它。

## 2. 配置扫描与导入作品

当前扫描依赖单独运行的 **Everything HTTP Server**，没有直接遍历磁盘的后备扫描方式。它用于导入或更新文件索引，不是打开软件、浏览已有记录或整理现有收藏的前提。

1. 单独安装 Everything，确保它已索引媒体所在目录，并启用其 HTTP Server。
2. 打开「设置 → 常规」，找到「Everything」，填写对应的服务地址并保存。默认是 `http://localhost:1223`；服务实际端口不同时请修改。
3. 进入要更新的媒体库，点击「扫描媒体库」，等待扫描完成后浏览结果。

扫描查询会向所配置的 Everything 服务发送媒体目录和查询条件。仅连接自己信任的服务，不要把该服务随意暴露到公网。连接失败时先检查 Everything 是否运行、HTTP 服务是否启用、地址和目录是否正确；无需删除现有库记录。

## 3. 浏览与匹配作品资料

在媒体库上方切换「表格」或「海报」，使用搜索、排序和筛选查找作品。打开作品后可查看目录、文件及已有资料。

在「海报与元数据」中点击「匹配元数据」；已有绑定时可使用「重新匹配」。选择正确的来源与候选作品，核对名称、年份、类型等信息后再应用。相同或近似名称可能对应不同作品，不要把自动搜索结果视为准确保证。

### 资料来源设置

配置入口是「设置 → 元数据」，修改后保存。无需配置每一个来源。

| 来源 | 配置与用途 |
| --- | --- |
| AniList | 当前接入无需用户凭据，用于动画作品信息和封面等资料。 |
| Bangumi | 可填写「Bangumi Access Token」；该项可选，公开资料查询不要求先填写。 |
| TMDB | 使用 TMDB 匹配电影或剧集资料时，必须填写自己的「TMDB API Key」。设置栏的“可选”表示可以不使用此来源，不表示 TMDB 能无 Key 工作。 |

这些 Key 和 Token 向对应平台申请，不是向 AnimeShelf 购买的服务，也不能用本机 API 令牌代替。隐藏显示只避免界面直接展示秘密，不等于磁盘加密。不要将密钥截图或含凭据的备份放到公开仓库。

手动搜索、匹配和刷新，以及已启用的自动匹配任务可能联网发送作品名等查询信息。服务访问、请求额度和数据权利遵循各平台条件，详见[隐私说明](PRIVACY.md)与[第三方说明](THIRD-PARTY.md)。

## 4. 分类、标签与合集

- 在作品详情的「媒体类型」选择自动、动画、影视或待确认。手动指定类型优先于资料识别结果和媒体库默认类型。
- 用标签组织自己的分类，可在「设置 → 自定义标签」维护标签。
- 打开作品目录的「季度与目录」，查看作品、季度和子目录分组。点击「设为合集」后，该目录会出现在侧栏的「合集」中；「取消合集」移除这一标记。这两个操作不移动磁盘文件。
- 「季度与目录 → 调整」包含分类和磁盘目录名等选项。提交前核对是否涉及真实目录重命名，不要将整个调整面板都理解为仅修改显示信息。

「设置 → 标签与命名」中的「正则重命名（显示名）」只处理界面显示名称；实际文件夹重命名是另一种操作。

## 5. 追番与心愿单

「追番」用于浏览季度与放送信息。作品上的星标操作显示为「收藏」或「取消收藏」，用于加入或移出收藏列表。

「心愿单」用于查看已收藏的作品。搜索结果中的「＋ 加入」可保存作品，打开已收藏项目后可使用「删除心愿单」。这些收藏操作不会自动下载作品，也不等于删除本地媒体文件。

从作品名称发起资源搜索会跳转到「下载」页，并把名称作为关键词。是否找到结果取决于来源站点及关键词。

## 6. 资源搜索

侧栏「下载」提供的是**搜索、结果列表和详情跳转**，不是下载客户端。

1. 打开「下载」。首次进入时会查询内置的 Bangumi.moe、ACG.RIP、动漫花园、Nyaa；空关键词显示最新发布。
2. 展开「渠道」，选择本次参与的来源。输入关键词，点击搜索或按回车提交。
3. 按需要排序、筛选合集或翻页，查看各来源的状态；某个来源失败时可单独重试。
4. 点击结果标题前往原站详情。浏览器运行时使用新标签页，桌面程序使用系统浏览器；后续访问受原站规则约束。

页面会保留当前会话已提交的查询与来源选择，再次进入时重新加载。来源地址内置，不能自行替换为其他网站。程序不代填站点账号或 Cookie，不绕过验证页，也不自动下载媒体文件。

站点不可用、限流、超时或解析失败会显示为对应来源的错误。下载搜索目前不支持无法安全校验目标的代理；检测到这类代理时会报错，不会静默改为直连。不要为解决搜索失败而关闭 TLS 或证书校验。内置搜索不代表来源站点保证可用，也不授予媒体内容的使用权。

## 7. 外观与壁纸

在「设置 → 外观」调整主题、显示和背景。显示设置和背景壁纸分别有「保存」按钮；预览满意后保存对应分区。

可选择纯色、图片、视频或 Wallpaper Engine 方式。图片和视频使用你自己的文件，软件不附带作品壁纸；仅选择 Wallpaper Engine 方式时需要相应外部软件及素材。请使用自己有权使用的图片或视频。

## 8. 数据位置、备份与恢复

### 数据保存在哪里

| 运行方式或内容 | 默认位置 |
| --- | --- |
| 从源码运行 | 项目目录下的 `data/` |
| 自行构建的便携程序 | EXE 所在目录下的 `data/` |
| 自动数据库备份 | 数据目录中的 `backups/auto/` |
| 手动数据库备份 | Windows 桌面，可在设置中修改 |
| 共享海报备份 | 数据目录中的 `backups/posters/` |

`data/` 中包括 `animeshelf.db`、设置与凭据，以及本地海报等应用数据。媒体库指向的视频和其他原始文件仍在原目录，不会存进数据库备份。

需要指定其他数据位置时，在启动前配置 `ANIMESHELF_DATA_DIR`；方法见[开发文档](DEVELOPMENT.md)。Electron 的浏览器会话与缓存另外使用 Windows 用户配置目录，本机服务登记默认位于 `%LOCALAPPDATA%/AnimeShelf/run/`。便携版免安装，但并非所有文件都保存在 EXE 旁。

### 创建备份

1. 打开「设置 → 备份与恢复」。
2. 按需要填写「自动备份目录」和「手动备份目录」，点击本分区的「保存」。留空时使用上表默认位置。
3. 如需保留海报，保持「备份时同步海报到共享海报库」选项开启。它默认开启，增量复制海报；数据库文件与海报库是分开的。
4. 点击「立即备份」，等待完成并记下保存位置。

每次后端启动会进行自动数据库备份，保留最近 10 份；这不是持续备份，也不是原始媒体文件备份。海报库不会按这 10 份数据库备份的规则一并清理。若自定义自动备份目录无效，程序会使用默认目录，请核对实际保存位置。

数据库及备份可能包含平台凭据、私人路径、收藏和历史配置。不要公开分享。重要视频、字幕等文件应另用自己的文件备份方案保存。

### 恢复备份

1. 在「恢复备份」中点击「查看可用备份」，或「选择 .db 文件…」。上传文件必须小于 35 MB；更大的备份放到已配置的备份目录后从列表选择。
2. 点击「预检」，查看数据库和路径检查结果。
3. 核对每个待处理路径。目录已移动时，填写正确的绝对路径，按实际情况「确认关联此目录及下级」；暂时找不到的可「保留为缺失条目」。
4. 确认无误后点击「确认应用恢复」，并阅读确认提示。

恢复会替换当前媒体库记录和设置，**不是把两份数据库合并**；恢复前程序会保存当前数据库备份。恢复保留现有磁盘名称，不会按备份重命名原始文件。仍应自行保存一份重要数据副本，不要只依赖自动保护。

海报优先从共享海报库补回，缺失时可能联网重新获取。只有 `.db` 文件时，不能保证离线恢复出所有海报；迁移时应同时保留需要的海报与完整应用数据。

### 升级与数据库兼容

升级或迁移前先退出程序，将完整 `data/` 复制到安全位置，并另行备份媒体文件。保留旧程序和数据副本，确认新版本工作正常后再整理旧文件。

当前版本拒绝打开或恢复**含手机同步结构的旧数据库和备份**，不会为其自动迁移或删表。看到不兼容提示时保留原文件，使用新的独立数据目录；需要访问原数据时使用与它兼容的程序。不要把旧 `.db` 直接覆盖进唯一的数据目录，也不要删除数据库表强行导入。其他来源的备份同样先预检，不能假定任意版本都兼容。

## 9. 涉及真实文件的操作

查看资料、修改显示名称与管理收藏，和操作磁盘文件不是一回事。**实际目录重命名、移动和删除会改变磁盘内容；删除是永久操作，不经过回收站。**执行前确认对象及路径，备份重要文件。

当前目录移动不支持跨磁盘卷。若操作报错，先阅读界面提示并检查原路径、目标路径和文件状态，不要立即重复删除或手动清理提示中的临时目录。文件保护和数据库备份不能代替原始媒体文件的备份。

## 10. 本机 API 与工具集成（进阶）

这是给自己的脚本或本机工具使用的接口，与作品资料来源的第三方 Key 分开。普通浏览、整理和匹配无需启用它，也无需创建令牌。

1. 进入「设置 → 外部 API」，勾选「启用专用外部接口」，按需要设置端口（默认 `3003`），点击「保存设置」。
2. 在「访问令牌」填写名称，优先选择「只读」，按需要设置有效期，再点击「创建」。
3. 立即安全保存完整令牌；关闭提示后无法再次查看。不再使用时撤销令牌。

接口默认关闭，启用后只监听本机 `127.0.0.1`。权限中的「数据编辑」允许修改资料，「文件管理（最高）」还允许物理重命名、移动和永久删除媒体目录，只应授予可信工具。

不要把令牌放进 URL、公开脚本或截图，不要把应用管理端口公开到网络。本机 API 的权限不等于隔离所有本机程序；能够直接读取数据库或访问管理接口的程序仍可能接触数据。完整调用与安全边界见[本机 API 文档](external-api.md)。
