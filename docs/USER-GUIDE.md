# AnimeShelf 桌面操作说明

## 媒体库与普通元数据

在设置中添加媒体库目录，按需要配置 Everything HTTP Server。导入后使用海报墙／列表浏览、搜索、排序和筛选。Everything 不随本程序捆绑。
人工指定的媒体类型优先于已确认元数据，随后才是自动识别和媒体库默认类型。媒体库类型只是默认值，不覆盖已有人工选择。

详情页可检查文件、修改展示信息和执行已有文件操作。重命名、移动和删除会影响实际文件；删除不是回收站操作。执行前核对对象与路径，重要数据先备份。

普通元数据支持 AniList、Bangumi 和 TMDB；TMDB 密钥、Bangumi 令牌通过设置由用户提供，默认不附带项目作者的凭据。仅在明确匹配、刷新或已启用的自动元数据任务中向这些提供方发送查询。数据和图片仍受各提供方条件与原权利人权利约束。

## 合集、追番与心愿单

保留现有合集整理、作品分组、追番和心愿单管理。可从作品名称发起资源搜索，名称会作为下载页关键词；这不意味着应用会自动下载文件。AI 编目、AI 工作台和找番不在本候选中，相关页面／接口／配置入口不可用。

## 下载来源

1. 打开侧栏“下载”，程序会查询内置的 Bangumi.moe、ACG.RIP、动漫花园、Nyaa，无需填写地址。首次为空关键词，显示最新发布。
2. 展开“渠道”勾选本次参与的来源，输入关键词后点击搜索，也可用回车提交；刷新会忽略短时结果缓存，但不绕过限流。
3. 可分页、排序、筛选合集、查看独立来源状态并重试，详情链接在系统浏览器打开；程序不自动下载媒体文件。
4. 当前会话保存关键词和来源选择，再次进入会重新加载上次已提交的查询。从心愿单进入则直接使用作品名搜索。不支持的旧来源选择会被过滤。

来源地址固定，不能通过设置或接口改为其他网站。请求路径由适配器生成；应用阻止内网／本机／保留地址、跨站链接和不安全重定向。四个来源的可用性及使用条件仍以各站实际情况为准。

首版下载请求不支持无法安全固定目标的代理。若检测到应用／系统／环境代理，会明确失败且不会静默直连；其他模块的代理行为不变。无需也不建议为了访问某站关闭 TLS 或证书校验。

旧版本保存的下载地址不会删除，但不再参与任何下载查询，也不通过普通设置导出；旧的地址配置接口返回 404。切换查询或离开页面会取消当前请求，迟到响应不会混入新结果。网站验证／限流／超时／解析失败会单独显示，不伪装为成功空列表；某站失败不影响其他来源。

## 壁纸与外部 API

壁纸使用用户自己拥有使用权限的文件，不随候选提供作品壁纸。外部 API 默认停用，仅本机监听，令牌角色和危险操作边界见 [外部 API](external-api.md)。

显示和壁纸设置统一放在「设置 → 外观」，显示与壁纸分别保存。视频壁纸在窗口失焦或页面隐藏时暂停并保留最后一帧，返回后自动继续播放。

本候选不包含手机应用、桌面配对、手机同步或配置导出。桌面备份仍可用，完整数据库备份须妥善保管。

## 数据位置与备份

便携版默认在 EXE 旁的 `data/` 保存 SQLite 数据库、设置、凭据、海报及运行状态。开发版使用项目数据目录；可用 `ANIMESHELF_DATA_DIR` 显式覆盖。

自动备份默认位于 `data/backups/auto`。手动备份默认到 Windows 桌面，也可由已有设置改目录。备份可能含历史凭据、个人路径、媒体库记录和下载来源；不要当作公开示例。不要把正在使用的数据库文件直接混入发布包。

恢复备份要先预检并确认路径。本候选使用独立数据目录，不能直接打开或恢复带手机同步结构的完整版数据库；检测到这类数据时拒绝操作并保留原文件，不自动删除或迁移旧数据。旧设置无法恢复不存在的模块。
